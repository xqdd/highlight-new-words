## 一、范围与对照

依据[英文阅读流畅度研究](../../deep-research/researches/2026-10/017-english-reading-fluency/README.md)，加入可在设备端运行的辅助。默认关闭，功能可分别调整；不宣称提升阅读速度或理解能力。

当前构建的滚动性能、原生绘制与体验取舍，以[最新性能验收](reading-performance-progress.md)为准；下文保留各轮实现和验收记录。

实际对照为本仓库修改前的扩展与相同网页 fixture，使用相同桌面和手机视口。验收要求：原文与复制内容一致、链接和代码保留、动态更新正常、开关可恢复、默认设置无新增干预、设置与备份可正常读写。词性用上下文标注样例检查，不能当成主句结构分析。

## 三、不纳入的功能

不提供正文排版、段落聚焦、阅读尺或当前段朗读。不接入 LLM、翻译接口、整段翻译、简单英文改写、段落摘要或背景生成。暂不做可靠性不足的主干提取、从句边界和强制意群切分，也不加入强制逐词闪现、自动滚动、打卡与阅读速度排行榜。已有生词译文与字幕功能继续沿用。

字母强调保留词首，提供比例、轻中重三档强度、每 1–5 个英文词强调一个以及最短词长。[JiffyReader 的实际算法](https://github.com/ansh/jiffyreader-public-archive/blob/master/src/services/documentParser.ts)和 [TextVide](https://github.com/Gumball12/text-vide/blob/main/packages/text-vide/src/index.ts)均强调词首；词尾、首尾和指定字母没有足够依据纳入。强度、间隔属于视觉偏好，不作阅读提速承诺。间隔从每段第一个英文词开始计数，短词占计数但不一定强调，数字不占计数。

## 六、长文往返滚动性能优化

验收对象为同一 Wikipedia Barack Obama 完整快照与同一浏览器视口，以优化前 3.1.0 实际构建作对照。除首屏、中部、末尾标注外，检查连续跳转、回首屏与真实滚轮上下往返的帧间隔、交互响应、CPU 和节点数量。基准不执行修改过内容的线上页面计时对比。

已实现离屏逐词视觉层回收，保留原 Text、生词 DOM 与可撤销分组；每帧最多分析一段，连续滚动停稳 90ms 后补标记。减少自有包装的计算样式读取、无效高亮查询及重复全页计数。页面移除整段时还原正文并释放索引及观察，多段同时移除后重新挂回仍保留完整正文。

以所有阅读功能与生词高亮同时开启测试，在顶部、中部、末尾各执行向下 24 次、向上 24 次真实滚轮事件，每次 520px、间隔 40ms，记录实际滚动位置。优化前后串行测量并各复核一轮：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 全流程 Task CPU | 26.54–26.65s | 11.30–11.79s |
| 末段滚轮往返耗时 | 8,899–9,015ms | 2,659–2,743ms |
| 末段帧间隔 p95 | 116.7–133.3ms | 16.7–16.8ms |
| 末段帧间隔最大值 | 200–266.6ms | 50ms |
| 末段超过 50ms 的帧数 | 64–71 | 0 |
| 返回首屏 Task CPU | 1.32–1.34s | 0.63–0.72s |

优化后顶部、中部、末尾滚轮往返的帧间隔 p95 均约 16.8ms。末轮阅读包装从 19,573 个降到 1,885 个；三处停稳后的目标标记分别为 81、127、188 项，关闭后整篇与逐段正文逐字一致，无阅读标记残留。连续跳转的 p95 仍约 33.3ms，因此这些结果只证明此固定长页的往返滚动明显改善，不代表所有页面、设备和交互都能达到 60fps。

两轮[优化前报告](/tmp/hnw-reading-performance/v310-before-threepoints-report.json)、[优化前复核](/tmp/hnw-reading-performance/v310-before-threepoints-repeat-report.json)、[优化后报告](/tmp/hnw-reading-performance/v310-candidate2-threepoints-report.json)、[优化后复核](/tmp/hnw-reading-performance/v310-candidate2-threepoints-repeat-report.json)保存在本机。回归覆盖离屏回收、生词节点保留、返回重绘、多子树移除与重挂、滚动暂停标注及停止时的完整还原。

独立代码复审与匿名指标比较判定优化版胜出，未发现阻断问题。直接跳转和停稳后的同步分析、布局仍可能带来短暂延迟，复测中个别输入响应为 118–179ms，后续应继续按具体页面取证。

## 七、多网站覆盖与动态评论复验

本轮对照为上述滚动优化后的 3.1.0 构建。已复现 YouTube 评论使用 `yt-attributed-string#content-text`、没有标准段落祖先时不进入阅读发现队列；生词高亮能出现，但词性与仿生阅读没有覆盖。实现补充限定在描述和评论区域的自定义文本容器，以及语义正文区域的 div、标题和表格。新增正文最初为空或中文、后续才填入英文时也注册视口观察；发现与渲染仍按帧限额运行。只有实际英文文本所在的块进入观察，空单元格与纯布局容器不占渲染额度；停稳后用真实可见区观察优先处理当前正文，预读区继续保留上下 800px 缓冲。

词性复现中 `we` 本身正常，`someone` 等复合不定代词被本地库归为名词；存在句 `there` 与部分 `what/how` 只有未映射标签。已补充封闭词表和上下文映射，区分存在句与地点 there、独立 what 与修饰名词的限定词，不把这些词统一强制归为代词。另覆盖缩写、`what someone said` 与 `what John said` 等用法；本地规则仍不能保证任意句子的词性分析完全准确。依据为 [Cambridge 不定代词](https://dictionary.cambridge.org/uk/grammar/british-grammar/pronouns-indefinite)、[what 用法](https://dictionary.cambridge.org/grammar/british-grammar/what)、[British Council 存在句说明](https://learnenglish.britishcouncil.org/free-resources/grammar/english-grammar-reference/it-there-dummy-subjects)。

## 八、快速往返与横向滚动复验

以本轮开始时保存的实际构建 `/tmp/hnw-scroll-round0` 为对照，检查快速上下往返、首次进入新区域、表格左右滚动的即时标记保留、补齐延迟、CPU 与节点峰值。当前实现为视口上下 1000px、左右 1600px 预读；支持 `IntersectionObserver.scrollMargin` 时，另扩张中间滚动容器左右各 800px 的裁剪范围，提前处理宽表格邻列。旧浏览器保留视口预读与近期缓存。离屏部分最多保留 64 块或 8000 个原文字符，超限后逐帧回收。连续滚动停稳 90ms 后才新增标注、同步生词样式或回收缓存，近期命中直接复用原标记。预读区内节点不属于离屏缓存，因此这不是整个页面 DOM 的绝对上限。

[滚动体验脚本](../scripts/qa/reading-scroll-experience.mjs)使用相同 Wikipedia 完整快照、视口与真实滚轮路线，逐 rAF 按原文字符偏移定位同一个词，检查词、实际词级标记、计算样式与标记节点身份。普通可撤销分组不算词级标记；新区域首次渲染与已读区域再次进入分开统计。快照没有现成可横滚表格，因此另用明确标为构造场景的 120 格宽表格，采样四角各一个词，执行真实横向 wheel、scrollLeft 与四角往返；不是全表每个词的逐词验收。探针本身有布局读取开销，正式 CPU 另用低干扰脚本测量。

## 九、正文范围过滤与复合词覆盖

## 十、独立标记范围与连续滚动

原文阅读与生词高亮分别配置过滤条件。生词侧入口为“外观 → 生词标记范围”，过滤总开关默认关闭，条件默认折叠；开启后可独立配置短文本词数、独立链接、辅助信息、标题、表格、按钮和导航。阅读侧保持现有默认过滤，修改任意一侧不覆盖另一侧。动态增删相邻文字会重新判断所属文字块，新增评论不会重建其他段落的标记；同时切换两侧范围时先清理旧阅读包装，避免撤销新生词标记。
